# atv4

## Форк: что отличается от апстрима

Это форк официального TVML-приложения kino.pub для Apple TV
(`kpapplication/atv4`). Апстрим подключён как remote `upstream`.

**Библиотека (фильтры)**

- **Год** одной кнопкой: первым пунктом «Свой диапазон…» в два шага
  («С какого года» → «По какой год»), затем готовые периоды по десятилетиям
  («2020-е», «2010-е»…, «до 1950»). В API уходит `year=FROM-TO`.
- **Жанр** и **Страны** с несколькими значениями: список с галочками,
  «Готово» применяет, «Сбросить» снимает. В API уходит `genre=1,3`.

**Шапка**

- Вместо пункта «ТВ» пункт **«История»**: отдельная страница с историей
  просмотров (сетка постеров, удержание на постере удаляет запись).

**Сеть**

- `js/hosts.js`: запасные зеркала API (`KINOPUB.apiHosts` в `js/consts.js`).
  Если запрос не доходит до сервера (обрыв, таймаут, блокировка), приложение
  само переключается на следующее зеркало, повторяет запрос и запоминает
  выбор. По кругу не ходит: одно зеркало пробуется не чаще раза в минуту.
- У запросов появился обработчик таймаута (раньше таймаут молча терял запрос,
  экран оставался на «Загрузке»), а не-JSON ответ при обрыве больше не роняет
  обработчик ошибок.
- Очистка кэша раз в 5 минут вместо каждых 5 секунд.
- `js/settings.js` не падает без `process.env` (в TVJS его нет), поэтому
  приложение работает прямо из исходников без сборки.

**Инструменты**

- `tools/build.js` собирает однофайловую версию в `dist/` (как на appkp.cc).
- `tools/test-filters.js` прогоняет настоящие модули в Node без приставки:
  фильтры, сериализация URL, таймаут, переключение зеркал.
- `.github/workflows/pages.yml`: при пуше в `year-range` тесты, сборка и
  публикация `dist/` на GitHub Pages.
- `.github/workflows/upstream-sync.yml`: раз в день проверяет апстрим и при
  новых коммитах открывает pull request `sync-upstream` → `year-range`.

### Как запустить на Apple TV

1. Адрес публикации: `https://ravorotnikov.github.io/atv4/` (собирается
   автоматически из ветки `year-range`).
2. В приложении MicroIPTV на Apple TV указать этот адрес как «плейлист»
   (так же, как указывается `appkp.cc`).
3. На вопрос «Открывать автоматически при запуске приложения?» ответить «Да».

### Разработка

```bash
node tools/test-filters.js   # тесты
node tools/build.js          # сборка в dist/
git fetch upstream && git merge upstream/main   # обновление из апстрима вручную
```
